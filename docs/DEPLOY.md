# Деплой PrintBot у хмару (безкоштовно)

Мета: бот працює 24/7 у хмарі, база даних — теж онлайн. Ваш комп'ютер нічого не тримає.

Потрібно три речі:

1. **База даних** — Neon (PostgreSQL, безкоштовно).
2. **Хостинг для бота** — Render (Docker, безкоштовно).
3. **GitHub-репозиторій** — Render деплоїть код звідти.

> Чому не «просто VPS»: для старту це зайві гроші й адміністрування. Схема нижче коштує 0 грн/міс.

---

## 1. База даних: Neon

1. Зареєструйтесь на [neon.tech](https://neon.tech) (можна через GitHub).
2. **Create project**:
   - Name: `printbot`
   - Region: `Europe (Frankfurt)` — найближчий до України.
   - Postgres version: за замовчуванням.
3. На сторінці проєкту натисніть **Connect** і скопіюйте рядок виду:

```
postgresql://neondb_owner:ПАРОЛЬ@ep-xxxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require
```

4. Це і є `DATABASE_URL`. Нікому не показуйте: у ньому пароль.

Безкоштовного тарифу (≈0,5 ГБ) вистачить на десятки тисяч замовлень: у БД зберігаються тільки метадані, а не самі файли.

**Важливо:** не використовуйте «pooled» рядок (`-pooler` у хості). У нас один довгоживучий процес, тому пряме з'єднання стабільніше й простіше.

### Локальна перевірка (необов'язково)

```bash
# у .env вставте DATABASE_URL з Neon
npm run db:deploy
npm run dev
```

Міграції створять таблиці в хмарній базі. Ваш комп'ютер при цьому нічого не зберігає.

## 3. Хостинг: Render

1. [render.com](https://render.com) → **New +** → **Web Service**.
2. Підключіть GitHub-репозиторій `printbot`.
3. Налаштування:
   - **Language / Runtime**: `Docker` (Render сам знайде `Dockerfile`).
   - **Instance Type**: `Free`.
   - **Region**: Frankfurt.
4. **Environment Variables** (Add from `.env.example`, але зі своїми значеннями):

| Змінна | Значення |
|---|---|
| `BOT_TOKEN` | токен від @BotFather |
| `DATABASE_URL` | рядок з Neon |
| `ADMIN_TELEGRAM_IDS` | `6590468340` |
| `PRINT_NAME` | `Друкарська, 48б` |
| `WORK_HOURS` | `щодня 18:00–22:00` |
| `PRICE_PER_PAGE_KOP` | `300` |
| `CARD_TRANSFER_ENABLED` | `true` |
| `CARD_NUMBER` | номер картки (або порожньо) |
| `CARD_RECIPIENT` | ім'я отримувача (або порожньо) |

`PORT` **не задавайте** — Render передає його сам, код його читає.

5. **Create Web Service**. Перший білд ~3–5 хв.
6. Перевірте:
   - логи містять `telegram polling started`;
   - `https://ВАШ-СЕРВІС.onrender.com/health` повертає `{"status":"ok"}`.

Міграції застосовуються автоматично при старті контейнера (`prisma migrate deploy` у `Dockerfile`), тому окремо нічого запускати не треба.

---

## 4. Пастка безкоштовного Render: засинання

Render Free **зупиняє** сервіс після ~15 хвилин без **вхідних HTTP-запитів**. Бот працює через long polling (сам ходить до Telegram), тому Telegram не «розбудить» сервіс, і бот буде офлайн.

Рішення — зовнішній пінг:

1. Зареєструйтесь на [cron-job.org](https://cron-job.org) або [UptimeRobot](https://uptimerobot.com).
2. Створіть перевірку:
   - URL: `https://ВАШ-СЕРВІС.onrender.com/health`
   - Інтервал: кожні 5–10 хвилин.
3. Готово: сервіс не засинає, бот відповідає цілодобово.

Ліміт Render Free — 750 годин/місяць на сервіс, а місяць — 744 години. Один сервіс якраз вкладається; не запускайте другий.

### Якщо пінг не подобається

Альтернативи без засинання:

| Варіант | Нюанс |
|---|---|
| **Koyeb Free** | постійний процес, але може вимагати картку для верифікації |
| **Fly.io** | платно за запитами, мінімальний безкоштовний ліміт |
| **Oracle Cloud Always Free** | повноцінна VM 24/7, але треба вміти адмініструвати Linux |
| **VPS за $3–5/міс** | найпростіший «завжди онлайн», якщо проєкт виросте |

Код від цього не змінюється: скрізь той самий Docker-образ і ті самі env-змінні.

## 5. Оновлення та бекапи

**Оновлення:** `git push` → Render перезібрати автоматично. Нові міграції застосуються при старті.

**Бекап бази:**

```bash
# раз на тиждень, локально (не потребує постійного запуску)
pg_dump "postgresql://...neon.tech/neondb?sslmode=require" > backup_$(date +%F).sql
```

Відновлення: `psql "postgresql://..." < backup_2026-11-10.sql`.

Neon на платному тарифі робить PITR сам; на безкоштовному — покладайтесь на дамп.

## 6. Чекліст безпеки

- [ ] `.env` не в git (перевірте `git status`).
- [ ] Токен бота не світиться в логах і скріншотах.
- [ ] Якщо токен засвітився — @BotFather → `/revoke` і оновити `BOT_TOKEN` у Render.
- [ ] Пароль Neon не в публічних репозиторіях; за потреби — rotate у Neon.
- [ ] Доступ до Render-акаунта захищений 2FA.

## 7. Що робити, якщо щось не так

| Симптом | Причина / дія |
|---|---|
| Бот мовчить, `/health` відповідає | Перевірте логи: чи `polling started`; чи не запущено **другий** інстанс із тим самим токеном (Telegram віддає апдейти лише одному) |
| `P1001: Can't reach database` | Неправильний `DATABASE_URL`, немає `sslmode=require`, або проєкт Neon видалено |
| `relation "users" does not exist` | Міграції не застосувались: перевірте логи білда, вручну `npm run db:deploy` з локального `.env` |
| Бот відповідає вдень і мовчить вночі | Сервіс засинає: перевірте пінг з розділу 4 |
| `409 Conflict` у логах | Одночасно працюють два екземпляри бота (наприклад, локально й у хмарі) — зупиніть один |
