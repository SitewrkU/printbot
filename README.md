# PrintBot

Telegram-бот для замовлень друку: клієнт надсилає PDF/DOCX, бот рахує сторінки й ціну, замовлення потрапляє в чергу до працівників друкарні.

> Стан проєкту: **E0** — скелет, реєстрація, ролі, адмінка працівників.
> Технічне завдання — [`docs/SPEC.md`](docs/SPEC.md).

## Стек

- Node.js 22+, TypeScript (strict)
- [grammY](https://grammy.dev) — Telegram-бот (long polling)
- Fastify — `/health` (пізніше — вебхуки оплати)
- Prisma + PostgreSQL
- Zod, Pino, Vitest

## Швидкий старт

```bash
# 1. Підняти Postgres локально (ПРОПУСТІТЬ, якщо DATABASE_URL вказує на Neon)
docker compose up -d

# 2. Налаштувати оточення
cp .env.example .env
#    вписати BOT_TOKEN (від @BotFather) і ADMIN_TELEGRAM_IDS

# 3. Встановити залежності та створити таблиці
npm install
npm run db:deploy

# 4. Запустити
npm run dev
```

Бот працює через long polling, тому публічний HTTPS для локальної розробки не потрібен.

### Windows / PowerShell

Якщо `npm` падає з `running scripts is disabled on this system`, використовуйте `npm.cmd` або дозвольте локальні скрипти:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

## Що вже працює (E0–E3)

- `/start` — реєстрація: ім'я → телефон (кнопка «поділитися номером» або вручну) → кімната → підтвердження.
- Кімната у форматі `25б` / `33п` (бічна/пряма); місце видачі фіксоване — `PICKUP_POINT`.
- Дані зберігаються; при наступних заходах реєстрація не повторюється.
- Профіль: перегляд і редагування імені, телефону, кімнати.
- Ролі: клієнт / працівник / адміністратор.
- Адмінка: список працівників, додавання за Telegram ID, зняття ролі.
- **Нове замовлення:** прийом PDF/DOCX як документів, підрахунок сторінок на сервері
  (PDF — точно, DOCX — орієнтовно), ліміти файлів/сторінок, копії, коментар,
  ціна `3 грн × сторінки × копії`, створення замовлення з номером `PB-0001`.
- **Кольоровий друк:** працівник може вручну змінити ціну (багато кольору/заливки)
  або відхилити замовлення; клієнт підтверджує нову суму.
- Оплата: готівка при отриманні або переказ на картку з кнопкою «Я оплатив»
  і ручним підтвердженням працівником.
- «Мої замовлення» — статус, сума, деталі; клієнт може скасувати, погодити ціну,
  позначити оплату або «Забрав».
- **Черга працівника:** вільні замовлення й «мої в роботі», «Взяти», «Готово»,
  пауза/продовження, зміна ціни, відхилення, повторне надсилання файлів,
  підтвердження оплати.
- **Блокування клієнтів:** працівник або адмін може заблокувати клієнта з картки
  замовлення (із зазначенням причини) та розблокувати у списку «🚫 Заблоковані».
  Заблокований клієнт не може створювати нові замовлення; наявні — обробляються далі.
- Сповіщення про замовлення й службові дії — **лише в групу працівників**
  (`STAFF_CHAT_ID`); у приватні чати не дублюються. Якщо група не задана —
  резервно надсилаються в ДМ активним працівникам/адмінам.
- **Оголошення** для всіх користувачів і перемикач «Прийом замовлень» (працівник/адмін).
  Пауза блокує старт нового замовлення, завантаження файлів і фінальне підтвердження;
  замовлення, які вже в черзі, обробляються далі.
- Клієнт отримує сповіщення, коли замовлення взято, готове, змінено ціну чи скасовано.
- У «Допомозі» та вітанні — інформація про розробника; у повідомленні про оплату
  карткою — необов'язкова картка «на каву» розробнику (`DEVELOPER_TIP_CARD`).
- Готові замовлення автоматично закриваються через 24 години.
- Старі завершені замовлення чистяться через `ORDER_RETENTION_DAYS` (типово 90)
  із збереженням добової статистики.
- `/health` і `/health/db` для моніторингу; `/health` показує задеплоєний коміт.

## Деплой

Покрокова інструкція для безкоштовного хостингу (Neon + Render + GitHub) — [`docs/DEPLOY.md`](docs/DEPLOY.md).

Docker-образ збирається з `Dockerfile`, міграції застосовуються на старті контейнера:

```bash
docker build -t printbot .
docker run --env-file .env -p 3000:3000 printbot
```

Мінімум для хмари: `BOT_TOKEN` і `DATABASE_URL` (Neon). `PORT` Render підставить сам.
